일관성 있는 협력 패턴 적용 → 이해하기 쉽고 직관적이며 유연한 코드

# 01 핸드폰 과금 시스템 변경하기

유사한 기능은 유사한 방식으로 구현해야 한다

유사한 기능이 일관성 없게 구현되어 있다면

- 새로운 구현 추가할 경우 → 어떤 구조를 따를지 매번 선택해야 함, 추가할수록 일관성 어긋남
- 기존 구현 이해해야 할 경우 → 직관, 예상과 달라 혼란, 심리적 장벽

# 02 설계에 일관성 부여하기

일관성 있는 설계를 위해

1. 다양한 설계 경험 익혀라
2. 널리 알려진 디자인 패턴 학습하고 변경 문맥 안에서 적용해보라

조건문을 객체 사이의 이동으로 대체하라

- 큰 클래스를 더 작은 클래스로 분리
    - 분리하는 기준은 변경 이유와 주기(단일 책임 원칙)
- 유사하게 행동하는 작은 클래스들을 역할로 추상화
    - 인스턴스들의 협력 패턴에 일관성 부여

훌륭한 추상화를 찾아 추상화에 의존하라

1. 변하는 개념을 변하지 않는 개념으로부터 분리하라
    1. 공통되는 부분을 추상화
    2. 변하는 부분들이 추상화를 구현
2. 변하는 개념을 캡슐화하라
    1. 변하지 않는 부분에 추상화를 합성
    2. 의존성 주입 등으로 추상화만 의존

캡슐화는 소프트웨어 내의 변할 수 있는 모든 개념을 감추는 것(변하는 어떤 것이든 감추는 것)

- 데이터 캡슐화: 클래스 내부 데이터 캡슐화
- 메서드 캡슐화: 클래스 내부 행동 캡슐화
- 객체 캡슐화: 객체와 객체 사이 관계 캡슐화 (합성)
- 서브타입 캡슐화: 서브타입의 종류 캡슐화 (다형성)

# 03 일관성 있는 기본 정책 구현하기

변경을 캡슐화하는 법

1. 변하지 않는 부분에서 변하는 부분 분리
    1. 변하는 부분의 공통점 추상화
2. 변하지 않는 부분이 이 추상화에만 의존하도록 관계 제한

캡슐화가 잘 된 코드는 추상적인 요소만으로 전체적인 협력 구조를 설명할 수 있다

- 변하지 않는 것과 추상화에 대한 의존성 만으로 전체적인 협력을 구현할 수 있다

개념적 무결성: 하나로 통합된 일련의 설계 아이디어를 반영하는 일관성 있는 시스템의 특성

- 코드를 한 번 이해하면 다른 코드도 이해할 수 있다
- 일관된 협력을 이해하면 변하는 부분만 독립적으로 이해해도 전체적인 구조 쉽게 이해할 수 있다
- 다소 이상한 구조가 되더라도 전체적인 일관성을 유지하는 설계를 선택하는 것이 현명

일관성 있는 협력 만들기 = 협력 패턴 발견하기

- 변경의 방향을 파악할 수 있는 날카로운 감각을 기르기
- 변경에 탄력적으로 대응할 수 있는 캡슐화 방법, 설계 방법 익히기
- 유사한 기능 구현을 위해 반복적으로 적용할 수 있는 협력 패턴 발견해나가기
